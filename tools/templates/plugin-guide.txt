사緣 API 끼워 넣기 묶음 __BUILD_ID__ (__ENV__)
그 앱의 routes 폴더에 이 폴더(__FOLDER__)를 통째로 복사하면 된다. npm install · 인터넷 필요 없음.

  사용자 화면  __WEB_URL__   (Web 서버 IIS — 화면 파일만)
  사緣 API     __API_URL__/api/…   (그 앱의 IIS 사이트 포트 __API_PORT__ · 경로 __BASE_PATH__)
               사용자 PC 브라우저가 직접 부른다. 이 화면 주소의 호출만 받는다(CORS): __WEB_ORIGINS__
  DB           __DB__   (이 API 만 접속)

  방화벽  사용자 PC 대역 · 개발 PC(__DEV_HOST__) → 이 서버 __API_PORT__ · 이 서버 → DB   (Web 서버 ↔ 이 서버 통신은 없다)
  https 로 온 호출만 받는다 (http 는 403)

────────────────────────────────────────
처음 한 번
────────────────────────────────────────
 1) 그 앱 폴더의 routes 아래에 이 폴더를 복사
      <그 앱>\routes\__FOLDER__\index.js · package.json · web.config · tools\ · config\ …

 2) 그 앱 main.js 에 한 줄 — Express 앱(app)을 만든 바로 뒤, ★ 그 앱의 CORS · 로그인 미들웨어보다 앞에
      그 앱의 mssql 설정(계정 포함)을 그대로 넘긴다 — 변수 이름(dbConfig)은 그 앱 main.js 에 맞춘다
        app.use('__BASE_PATH__', require('./routes/__FOLDER__')({ db: dbConfig }));
      · DB 이름은 사緣 것(__DB_NAME__)을 쓴다 (그 앱 설정의 database 는 무시) — 그 계정에 __DB_NAME__ 읽기·쓰기 권한 필요
      · 사緣 전용 DB 계정을 쓰려면 대신:  app.use('__BASE_PATH__', require('./routes/__FOLDER__'));  + 4) .env 의 DB_USER · DB_PASSWORD
      · ESM(import) 앱이면:  import sasystem from './routes/__FOLDER__/index.js';  app.use('__BASE_PATH__', sasystem({ db: dbConfig }));
    · 그 앱이 express.json() · 세션을 먼저 써도 괜찮다 (사緣은 자기 세션을 X-Sasystem-Session 헤더로 따로 쓴다)
    · CORS · 로그인 미들웨어보다 앞이어야 하는 이유: 사緣 API 는 다른 주소의 화면(__WEB_URL__)이 부르므로
      OPTIONS 사전 확인 요청이 사緣까지 와야 하고, 사緣의 CORS(허용 화면만)가 답해야 한다

 3) 그 앱의 web.config <iisnode … /> 확인
      nodeProcessCountPerApplication="1"   ★ 필수 — 사緣은 데이터를 메모리에 두고 DB 에 저장한다.
                                            프로세스가 2개 이상이면 서로 덮어써 데이터가 사라진다
      promoteServerVars="REMOTE_ADDR,HTTPS" ★ 필요 — REMOTE_ADDR: 사용자 IP (열람 기록 · 횟수 제한 · 개발 PC 확인)
                                            HTTPS: http 로 온 호출 거절. 그 앱이 이미 다른 값을 쓰면 쉼표로 이어 붙인다
    그 앱의 IIS 앱 풀: 고급 설정 → "겹친 재활용 사용 안 함" = True (재시작 순간 프로세스 2개 방지)
    Node.js 22 이상 (그 앱 web.config 의 nodeProcessCommandLine 이 가리키는 node.exe)
__HTTPS_STEP__

 4) 비밀 설정 — routes\__FOLDER__ 에서
      copy .env.example .env          → SESSION_SECRET · DATA_KEY 채우기 (DB 계정은 2)에서 넘겼으면 비워 둔다)
                                         개발 화면(npm run dev)을 쓰면 DEV_LOGIN_KEY (개발 PC 의 SASYSTEM_DEV_KEY 와 같게)
      copy config\admins.example.js config\admins.js
      node tools\hash-password.mjs "새 관리자 비밀번호"   → 결과를 admins.js 의 passwordHash 에

 5) DB 준비 — 표는 처음 시작할 때 없는 것만 자동으로 만든다 (그 계정에 표 만들기 권한이 있을 때)
    권한이 없으면 DB 담당자가 sql\setup.sql 실행 (목적별 표 SA_APPLICANT · SA_MATCH … · 표·열 설명 포함)
    예전 한 표(SA_DOC)에 데이터가 있으면 처음 시작할 때 새 표로 옮긴다 (SA_DOC 은 백업으로 남는다)
    (사緣 전용 계정을 새로 만들 때만: .env 에 DB_ADMIN_USER/DB_ADMIN_PASSWORD 를 잠시 넣고  node tools\db-setup.mjs)

 6) 그 앱의 IIS 앱 풀 재시작
      Restart-WebAppPool <그 앱의 앱 풀 이름>

 7) 확인 — 사내 PC 브라우저에서 (DNS 이름 주소로 — 인증서 이름과 맞아야 한다)
      __API_URL__/api/health   → {"ok":true, …}   안 열리면 방화벽(사용자 PC → __API_PORT__) · DNS · 인증서
    http://… 로 부르면 403 (https 만) 이 맞다
    이어서 화면 __WEB_URL__ 을 열어 로그인 확인
    "서버에 연결하지 못했어요" 면 F12 → Console 에 CORS 오류가 있는지 — 있으면 화면 주소가 위 허용 목록과 다른 것
      (.env 의 CORS_ORIGINS 에 그 주소를 더하고 앱 풀 재시작)
    사내 인사 API 재확인을 켰으면
      node tools\sso-test.mjs --empno <사번>
    실패하면 그 앱의 iisnode 로그에서 [sasystem] 로 시작하는 줄 (원인 / 해결)
    시작에 실패해도 그 앱은 그대로 돈다 — 사緣 API 만 503 으로 답하고, 30초 뒤 다음 요청 때 다시 시작해 본다
