사緣 API 끼워 넣기 묶음 __BUILD_ID__ (__ENV__)
그 앱의 routes 폴더에 이 폴더(__FOLDER__)를 통째로 복사하면 된다. npm install · 인터넷 필요 없음.

  사용자 화면  __WEB_URL__   (Web 서버 IIS — /api 를 아래 주소로 넘긴다)
  사緣 API     __API_URL__/api/…   (그 앱의 IIS 사이트 포트 __API_PORT__ · 경로 __BASE_PATH__)
  DB           __DB__

────────────────────────────────────────
처음 한 번
────────────────────────────────────────
 1) 그 앱 폴더의 routes 아래에 이 폴더를 복사
      <그 앱>\routes\__FOLDER__\index.js · package.json · web.config · tools\ · config\ …

 2) 그 앱 main.js 에 한 줄 — Express 앱을 만든 뒤, 그 앱의 404·오류 처리보다 앞에
      CommonJS (require 를 쓰는 앱):  app.use('__BASE_PATH__', require('./routes/__FOLDER__'));
      ESM (import 를 쓰는 앱)      :  import sayeon from './routes/__FOLDER__/index.js';
                                      app.use('__BASE_PATH__', sayeon);
    · app 은 그 앱의 Express 변수 이름에 맞춘다
    · 그 앱이 express.json() · 세션을 먼저 써도 괜찮다 (사緣은 자기 세션 sayeon.sid 를 따로 쓴다)

 3) 그 앱의 web.config <iisnode … /> 확인
      nodeProcessCountPerApplication="1"   ★ 필수 — 사緣은 데이터를 메모리에 두고 DB 에 저장한다.
                                            프로세스가 2개 이상이면 서로 덮어써 데이터가 사라진다
      promoteServerVars="REMOTE_ADDR"     권장 — Web 서버(__WEB_HOST__)를 확인하고 사용자 IP 를 기록한다
    그 앱의 IIS 앱 풀: 고급 설정 → "겹친 재활용 사용 안 함" = True (재시작 순간 프로세스 2개 방지)
    Node.js 22 이상 (그 앱 web.config 의 nodeProcessCommandLine 이 가리키는 node.exe)
__HTTPS_STEP__

 4) 비밀 설정 — routes\__FOLDER__ 에서
      copy .env.example .env          → SESSION_SECRET · DB_USER/DB_PASSWORD · DATA_KEY 채우기
      copy config\admins.example.js config\admins.js
      node tools\hash-password.mjs "새 관리자 비밀번호"   → 결과를 admins.js 의 passwordHash 에

 5) DB 준비 — routes\__FOLDER__ 에서 (.env 에 DB_ADMIN_USER/DB_ADMIN_PASSWORD 를 잠시 넣고)
      node tools\db-setup.mjs --check     바꾸지 않고 상태만
      node tools\db-setup.mjs             DB · 앱 계정 · 테이블 만들기 → 끝나면 .env 의 DB_ADMIN_* 지우기
    (DB 담당자가 직접 만들 때는 sql\setup.sql)

 6) 그 앱의 IIS 앱 풀 재시작
      Restart-WebAppPool <그 앱의 앱 풀 이름>

 7) 확인 — API 서버와 Web 서버 브라우저에서 (DNS 이름 주소로 — 인증서 이름과 맞아야 한다)
      __API_URL__/api/health   → {"ok":true, …}
    Web 서버에서 화면을 열어 로그인 확인 (Web 서버의 web\_deploy\check-web.ps1 이 /api 전달까지 확인한다)
    사내 인사 API 재확인을 켰으면
      node tools\sso-test.mjs --empno <사번>
    실패하면 그 앱의 iisnode 로그에서 [sayeon] 로 시작하는 줄 (원인 / 해결)
    시작에 실패해도 그 앱은 그대로 돈다 — 사緣 API 만 503 으로 답하고, 30초 뒤 다음 요청 때 다시 시작해 본다

────────────────────────────────────────
업데이트 (코드만 바뀌었을 때)
────────────────────────────────────────
  index.js · tools\ · sql\ · web.config · package.json 만 덮어쓰기
  .env · config\admins.js 는 그대로 둔다
  → 그 앱의 IIS 앱 풀 재시작 (routes 하위 파일은 iisnode 가 바뀐 것을 알아채지 못한다)

되돌리기: 덮어쓰기 전에 routes\__FOLDER__ 폴더를 통째로 복사해 두고, 문제가 있으면 다시 복사 → 앱 풀 재시작
